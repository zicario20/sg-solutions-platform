# M002 Help Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify the complete bounded M002 public bilingual Help Center on top of the approved M001 Astro website.

**Architecture:** Keep the public app static-first. Typed repository content is filtered through a source-neutral query service and emitted as server-rendered pages plus minimized locale search indexes; vanilla JavaScript adds search/filter/feedback enhancement. Public contracts reserve a Sanity adapter boundary without requiring credentials or importing private knowledge, RAG, chat or portal behavior.

**Tech Stack:** Astro 7.1.6, TypeScript 6.0, Tailwind CSS 4/global CSS, Vitest 4.1.10, Playwright 1.62.1, Biome 2.5.6, pnpm 11.18.0, Turborepo 2.10.8.

## Global Constraints

- Spanish routes use `/recursos/`; English routes use `/en/resources/`.
- The exact M001 logo, Manrope/Inter typography and approved navy/cobalt/cyan/green/gold/light tokens remain unchanged.
- Public projections contain only `public`, `published`, current records and never operational client fields.
- Search query text never leaves the browser and never enters analytics payloads or URLs.
- No live CMS credentials, AI answer, RAG, chat, portal lookup, feedback persistence or vendor analytics may be simulated.
- Existing `/preguntas-frecuentes/` and `/en/faq/` become compatibility redirects to the new canonical FAQ routes.
- Core reading and browse navigation work without JavaScript; progressive behavior has honest failure states.
- WCAG 2.2 AA, 44×44 CSS-pixel controls, 320–1440 px responsive behavior, 200% zoom and reduced motion are mandatory.
- Work test-first, preserve all M001 behavior, use exact dependency pins and add no dependency unless the implementation cannot be expressed safely with the existing stack.

```ts
export type KnowledgeStatus = "draft" | "in_review" | "approved" | "published" | "review_due" | "stale" | "superseded" | "archived";
export type KnowledgeAudience = "public" | "authenticated_client" | "internal_staff" | "ai_public" | "ai_internal";
export type KnowledgeType = "faq" | "article" | "guide" | "checklist" | "glossary" | "program";
export type ContentRisk = "low" | "medium" | "high";

export function toPublicKnowledge(record: KnowledgeRecord, at: Date): PublicKnowledgeRecord | null {
  if (record.status !== "published" || !record.audiences.includes("public")) return null;
  if (evaluateFreshness(record, at) === "stale" && record.riskLevel !== "low") return null;
  return pickPublicFields(record);
}
```
