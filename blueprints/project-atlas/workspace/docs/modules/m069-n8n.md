# M069 - n8n Integration Layer

- Status: controlled foundation implemented; provider disabled.
- Operational activation: pending Product Owner approval, deployment, security review, and provider configuration.

## Scope implemented

M069 provides typed, fail-closed contracts for n8n instance profiles, workflow references and versions, activity bindings, credential references, execution requests, and unverified webhook candidates. The database schema preserves those records without storing credential values or external payloads.

## Authority boundaries

- M068 remains the canonical workflow and durable business-state authority.
- n8n may become an adapter for approved integrations only.
- A successful node, HTTP response, or n8n execution cannot complete a service, payment, entitlement, or workflow stage.
- Canonical transitions remain behind domain commands, authorization, idempotency, audit, and reconciliation.

## Disabled capabilities

No n8n instance connection, credentials, workflow activation, execution dispatch, webhook acceptance, callback delivery, or background job is active. Credentials are references only and no secret value is stored, exported, logged, or injected by this module.

## Activation prerequisites

1. Deploy and secure a self-hosted or approved managed n8n instance.
2. Approve worker isolation, network policy, secrets, backup, monitoring, and recovery runbook.
3. Create reviewed workflow and typed input/output contracts.
4. Configure signed webhooks, replay handling, idempotency, and reconciliation.
5. Complete independent security review and explicit Product Owner activation approval.
